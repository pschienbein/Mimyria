# Mimyria

Machine Learning Accelerated Theoretical Condensed-Phase Spectroscopy Made Simple

## Examples

We provide two types of examples. First, the *low-level* examples demonstrate how training, prediction, RMSE calculation, and spectra computation are carried out manually, thereby explaining the underlying scripts in detail.

Each example contains a *do.sh* file that outlines the **mimyria** commands required to generate IR and Raman spectra, either using the low-level API or the autotrainer.

### Data

We provide example test and training sets, as well as one MD trajectory from the accompanying publication. These datasets are relatively large and are therefore not included in the GitHub repository. Please run the provided *download.sh* script to download the required data necessary to execute the examples.

The data is compressed using *zstandard*. If you encounter an error such as *"Creator zstd not found"*, this indicates that **mimyria** was compiled without *zstandard* support. The Makefile automatically detects whether the required development packages of *zstandard* (libzstd) are available at compile time and prints a warning if not. While these libraries are typically present on most systems, if they are missing, you can resolve the issue in one of the following ways:

1. Install the development packages for libzstd and recompile **mimyria** with *zstandard* support enabled.
2. Decompress all provided data files manually and modify the example scripts to use the uncompressed versions.

### Autotrainer

The *autotrain* directory contains a reduced example illustrating how to use the autotrainer to iteratively train APT- and PGTNNs within **mimyria** with minimal user intervention. Compared to the autotraining workflow presented in the accompanying publication, this example is significantly simplified to save time and disk space.

In the paper, the workflow is based on 80 NVE trajectories, generating an independent test set of 100 configurations and a training set of 200 configurations, followed by 20 training iterations.
In contrast, this example uses only a single trajectory, generates a test set of 10 configurations, and performs a total of 3 training iterations.

While this reduced procedure is sufficient to illustrate the workflow, a production run should include more trajectories and more extensive training and testing.

The autotrainer will use *CP2k* to calculate APTs and PGTs as needed and automatically perform training/prediction. In order to function properly a *force_eval.inc* file needs to be present in the parent directory, specifying the *FORCE_EVAL* section used by *CP2k*, defining the DFT setup. Furthermore, it requires two run scripts, *run-cpu.sub* and *run-gpu.sub* to submit jobs on either CPU or GPU nodes. The former will be used to run *CP2k* to generate the reference data, the latter will be used to run **mimyria** for training and prediction. Examples for these files are provided as well, but the **SBATCH commands need to be adjusted depending on your HPC hardware**. It is also possible to disable the submission of dedicated jobs, by setting *use_submit_decorator_cpu: 0* and/or *use_submit_decorator_gpu: 0* in the *state.yaml* that is generated by the autotrainer.
